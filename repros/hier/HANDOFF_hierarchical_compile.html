Full-Graph Compile with Hierarchical Compilation

Compile Granite 3.3's entire causal-LM forward as one torch.compile graph, with all decoder layers sharing a single invoke_subgraph body (compile-once), correct and token-matching on the Spyre card. This is where the work stands and what remains to ship.

Bottom line

Eager path is green (5/5 token-match vs HF CPU). The whole-forward compiled path is 0/5 (max_diff 13.76), blocked on the Inductor invoke_subgraph work being incomplete and uncommitted in torch-spyre.

Exactly one PR exists — torch-spyre #3647, the foundation. Everything else lives as dirty/untracked changes in two working trees. Five PRs need creating in dependency order; the single high-uncertainty item is Blocker 3 (open, device-proven).

The numeric fix (Blocker 6) is fully device-verified — all four discriminators 0.000000. It's the cleanest piece and gates correctness once the graph runs.

How the pieces fit

The whole forward — embed×multiplier → 40-block loop → norm → lm_head → /logits_scaling — becomes one compiled graph. Each decoder layer is wrapped in torch.compiler.nested_compile_region, so all layers reuse a single invoke_subgraph HOP body. That keeps compile time flat regardless of layer count (compile-once), instead of compiling 40 blocks individually with an eager prologue/epilogue.

Two host-side behaviors must stay outside the graph: RoPE (its cache-extend does .item()-driven CPU fancy-indexing) is hoisted so the body consumes selected_freqs as a graph input; and the in-place KV mutation is preserved (copy-free, via auto_functionalize) while the aliasing return is dropped, because invoke_subgraph rejects a subgraph output that aliases a subgraph input.

Watch-outs the incoming engineer will hit

  • Co-mingled dirty tree. torch-spyre changes span Blockers 1/2/3 and the separate Blocker 6 fix, all dirty in one tree on the unrelated branch perf/embedding-gather-optimal-layout. Splitting into PR-A/B/C/D is per-hunk surgery — one stray git checkout loses work. Snapshot before splitting.
  • Design doc drift. INVOKE_SUBGRAPH_LAYOUT_DESIGN.md proposes an approach the shipped code did not take (parent-side push + reverse MultiOutput). Annotate or supersede it; don't build from it.
  • Structural assumption unvalidated. The _subgraph_input_stls approach assumes one InvokeSubgraph per body. A shared body reused across call-sites with different operand STLs would break first-match. Unproven — flag if you keep that path.
  • Rebuild rule. Python-only _inductor edits need no rebuild; C++ changes need build-torch-spyre.sh --local-pytorch. After _inductor edits, move the inductor cache aside (TORCHINDUCTOR_CACHE_DIR) or stale codegen bites.
  • Device runs. Single-tenant VFIO card + real Granite weights; can't run in normal CI. Don't manual_seed in device repros; don't kill/relaunch to clear VFIO; move caches aside, never recursively delete.
